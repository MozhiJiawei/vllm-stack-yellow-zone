结论

不完整 AllReduce 对其他算子的影响不是“所有低并行算子都会阻塞”，而是明显依赖算子内部执行路径和 tiling。 首轮确认 FFN 阻塞；第二轮新发现集中在归约、排序以及 batch=1 的增量注意力路径。

ReduceSum 与 Sort 均稳定阻塞 rows=1 和 rows=4 都满足 X_ONLY PASS、contention BLOCKED，说明外层 rows 数量不是决定因素。
IncreFlashAttention 对 batch 敏感 batch=1 阻塞，而同一 KV/head 配置下 batch=4 通过，存在明确的 shape/tiling 分界信号。
不是通用 Vector 饥饿 Add、Mul、激活、Cast、Softmax 在 rows=1/4 均通过，问题更接近特定 kernel 同步路径。
Cube 场景暂未发现坏例 MatMul、BMM、AddMM、Conv、QuantBatchMatmul 共 11 个 case 全部通过。
